# FE integration: EVENT_JOIN and MEDIA_UPLOAD QR links are now backend-only

Shipped 2026-09-14. Sequel to `default-qr-links-fe-integration.md` — read that one first if you
haven't. Breaking for any FE flow that lets a host create, edit, revoke, or delete a generic invite
or gallery-upload code by hand; additive for everything else (`labelKey` is a new, optional field).

## What changed

`EVENT_JOIN` and `MEDIA_UPLOAD` links are now fully backend-owned. Only the backend mints them (on
activation) and edits them (on a plan change) — a host can no longer create, patch, revoke, or
delete either type, even the ones your UI already has an affordance for.

- `POST /api/events/{eventId}/qr-links` with `targetType: "EVENT_JOIN"` or `"MEDIA_UPLOAD"` now
  returns `409` with `errorCode: 5068` (`error.qr_shared_link_host_managed`), for every caller,
  host included.
- `PATCH /api/qr-links/{id}`, `POST /api/qr-links/{id}/revoke`, and `DELETE /api/qr-links/{id}` now
  return the same `409`/`5068` whenever `id` names a link with `autoGenerated: true`.

`targetType: "INVITATION"` (a personal, per-recipient code) is entirely unaffected — hosts keep
full create/patch/revoke/delete on those, exactly as before.

**Do this:** remove any UI affordance for creating a generic invite or gallery-upload code by hand.
The create form should only ever be reachable for a personal, per-invitee code from now on. For the
two auto-generated links, drop the edit/revoke/delete controls entirely and show them read-only,
with a short explanatory label like "Managed automatically" — `autoGenerated: true` is exactly the
field to key this off of, unchanged from the original default-QR-links release.

`GET /api/events/{eventId}/qr-links`, `.../stats`, and `GET /api/qr-links/{id}` are unaffected —
hosts keep read access to the two default links, same as any other link.

## New: `labelKey` for localizing the two default titles

The two default links now ship with a real title instead of `null` ("Untitled"), plus a stable
`labelKey` your FE can resolve against its own translation catalog for the viewer's selected UI
language:

```jsonc
{
  "id": "...",
  "targetType": "EVENT_JOIN",
  "label": "Event Invite",        // English fallback, set server-side
  "labelKey": "qrLink.default.eventJoinLabel",  // <-- new, null for host-created links
  "autoGenerated": true,
  // ...
}
```

**Do this:** render `labelKey ? t(labelKey) : label`. `labelKey` is non-null only for the two
default links; every host-created link (including a grandfathered `EVENT_JOIN`/`MEDIA_UPLOAD` link
made before this shipped) keeps `labelKey: null` and should render `label` directly, since the host
wrote that themselves. The two keys to add to your translation catalog, with the English text the
backend currently ships as the `label` fallback:

- `qrLink.default.eventJoinLabel` → "Event Invite"
- `qrLink.default.mediaUploadLabel` → "Gallery Upload"

## What did not change

- No change to capacity behavior: `EVENT_JOIN`'s `maxGuests` still auto-adjusts to the plan's member
  ceiling on upgrade/downgrade, as described in `default-qr-links-fe-integration.md`. `MEDIA_UPLOAD`
  still has no guest limit.
- A previously-absent `MEDIA_UPLOAD` default link may now appear after a plan change that turns on
  Gallery upload for an event that didn't have it at creation. Nothing new to build for this — it
  shows up in the same list the same way an upgrade already refreshes `maxGuests` — but don't assume
  the two default links are fixed at two (or even one, if Gallery was off) from the moment a host's
  dashboard first loads after activation.
- A link made before this shipped (`autoGenerated: false`, `targetType: EVENT_JOIN` or
  `MEDIA_UPLOAD`) keeps working exactly as it always has — it's grandfathered, not migrated, so it
  remains fully host-manageable.

## Checklist

- [ ] Remove any create/edit/revoke/delete UI for `EVENT_JOIN`/`MEDIA_UPLOAD` links — only
      `INVITATION` links go through those flows now.
- [ ] Handle `409`/`5068` on the four mutation endpoints as a hard stop, not a retryable error.
- [ ] Render `labelKey ? t(labelKey) : label` for every link, and add the two translation keys
      above to your catalog.
- [ ] Don't assume the auto-generated link count is fixed after activation — a plan change can add
      a `MEDIA_UPLOAD` link that wasn't there before.
